# Module selection

Choose the smallest supported set. A module earns inclusion when its page types will hold recurring project knowledge, not because the project might touch that subject once.

| Module | Use when the project repeatedly needs |
| --- | --- |
| `software` | Architecture, technical decisions, dependencies, or incidents |
| `product` | Users, product problems, discovery, or experiments |
| `business` | Business model, stakeholders, commercial assumptions, or economics |
| `research` | Claims, evidence, contradictions, or open questions |
| `marketing` | Customer evidence, positioning, messages, channels, or campaigns |
| `operations` | Processes, ownership, dependencies, cadence, or delivery risks |

The core wiki already includes project overview, decisions, concepts, inbox, sources, index, and log. Do not select a module merely to duplicate those core areas.

If a needed work type does not fit, initialize the core and supported modules. Record the missing module as an unresolved design decision instead of inventing a one-off directory structure.
