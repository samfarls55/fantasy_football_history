# Project interview

Inspect the target first. Infer answers from existing files when the evidence is clear, and state those inferences for correction. Ask the remaining questions in one compact batch unless an answer changes what must be asked next.

Use no more than five questions:

1. What is this project, and what will this directory produce?
2. Who or what uses the output, and what does success mean?
3. What belongs inside this project, and what belongs outside it?
4. Which durable constraints or non-negotiable conventions govern the work?
5. Which work types occur here: software, product, business, research, marketing, operations, or another type that needs a custom module later?

Do not use current tasks, deadlines, or temporary priorities as root `AGENTS.md` context. Record those in the wiki after initialization when they are material.
