# Domain docs

This is a single-context repository.

## Before domain work

Read GLOSSARY.md at the root and relevant ADRs in docs/adr/.
If either is absent, proceed silently. Create them when actual
terminology or architectural decisions need recording.

Use the glossary's vocabulary in issues, code and tests.
Surface conflicts with existing ADRs before overriding them.

## Product contracts

Read SPEC.md for requirements.
For interface work, also read DESIGN-BRIEF.md.
For record calculations or attribution, read docs/metrics.md.
